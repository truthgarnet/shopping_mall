## productSeq 예외처리

이번에는 커스텀 예외처리 하지않은 `상품이 존재하지 않은 경우`에는 어떤 오류가 발생할 지 궁금했다.

OrderServiceTest를 통해서 직접 테스트를 진행한 결과, 아래와 같이 오류가 발생했다.

```
java.lang.NullPointerException: Cannot invoke "com.truthgarnet.shopping.product.ProductEntity.getStock()" because "product" is null
 at com.truthgarnet.shopping.order.OrderService.insertOrders(OrderService.java:63)
 at org.springframework.aop.support.AopUtils.invokeJoinpointUsingReflection(AopUtils.java:359)
 at org.springframework.aop.framework.ReflectiveMethodInvocation.invokeJoinpoint(ReflectiveMethodInvocation.java:190)
 at org.springframework.aop.framework.ReflectiveMethodInvocation.proceed(ReflectiveMethodInvocation.java:158)
 at org.springframework.transaction.interceptor.TransactionInterceptor$1.proceedWithInvocation(TransactionInterceptor.java:133)
...
```

기존 코드는 다음과 같다.

```java
List<OrderItemRequest> items = orderRequest.getItems();

List<Long> productSeqs = items.stream().map(item -> (item.getProductSeq())).collect(Collectors.toList());

List<ProductEntity> products = productRepository.findByProductSeqInOrderByProductSeqAsc(productSeqs);
   
 for (OrderItemRequest orderItem : orderRequest.getItems()) {
            ProductEntity product = productMap.get(orderItem.getProductSeq());
            int stock = product.getStock();

            if (stock - orderItem.getQuantity() >= 0) {
                stock -= orderItem.getQuantity();
                product.setStock(stock);
            } else {
                throw new CustomException("OUT_OF_STOCK", product.getProductName() + " 는 재고가 부족한 상품입니다.");
            }
            productRepository.save(product);
        }
```

처음에는 DB에서 존재하지 않는 상품을 조회했기 때문에 `ProductEntity`가 `null`로 조회되었다고 생각했다.

하지만 다시 확인해보니 `findByProductSeqIn...()`과 같이 여러 데이터를 `List`로 조회하는 경우, **존재하지 않는 상품이** `<strong>null</strong>`**로 List에 포함되는 것이 아니라 DB에 존재하는 상품들만 조회된다.**

예를 들어 요청이 다음과 같다고 가정한다.

```
요청 productSeq : [1, 2, 999]

DB에 존재하는 상품 : [1, 2]
```

조회 결과는 다음과 같다.

```
products : [Product(1), Product(2)]
```

즉, 상품 조회 자체에서 NPE가 발생하는 것이 아니라 존재하지 않는 상품 번호로 Map을 조회한 뒤 변한된 null 객체의 메서드를 호출하면서 발생한 것이다.

---

### 고민 1. 상품 존재 여부를 먼저 조회해야 할까?

처음에 생각했던 방식은 `existsById`였다.
존재하는 객체들만 findBy를 하면 되지 않을 까 생각했는 데

```
1. 존재 여부 확인
2. 상품 데이터 조회
```

라는 같은 상품에 대하면 두 번 조회가 발생할 수 있다.

### 고민 2. Optional를 사용하면 되지 않을까?

그래서 처음에는 반환 타입을 `List<ProductEntity>`에서 `Optional`로 변경하는 방법을 생각했다.

`Optional`에는 값이 존재하지 않을 경우 예외를 발생시킬 수 있는 `orElseThrow()`가 있기 때문이다.

```java
products.orElseThrow(
  () -> new CustomException("PRODUCT_NOT_FOUND", "존재하지 않는 상품입니다.")
);
```

하지만 여기에는 문제가 있었다.

여러 상품을 조회하는 상황에서 `Optional<List<ProductEntity>>`를 사용하더라도, **조회 결과 List 자체가 존재하는지만 확인할 뿐 요청한 상품 중 어떤 상품이 누락되었는지는 알 수 없다.**

또한 여러 건을 조회하는 Repository 메서드는 일반적으로 조회 결과가 없더라도 `null` 대신 빈 `List`를 반환하기 때문에, 이런 상황에서 `Optional<List<...>>`를 사용하는 것 자체가 큰 의미가 없다고 판단했다.

따라서 다시 `List<ProductEntity>` 형태로 되돌렸다.

### 고민 3. Set을 사용해야할까?
처음에는 List<Long>만 사용해서 존재하지 않는 productSeq를 찾아도 되지 않을까 생각했다.

하지만 List의 contains()는 내부적으로 요소를 순차적으로 탐색하기 때문에 시간 복잡도가 O(n)이다.

따라서 요청으로 받은 productSeqs의 각 값을 조회된 상품 목록과 비교한다면,
```
요청 상품 개수: n
조회된 상품 개수: m
```
일 때 전체 비교 비용은 최악의 경우 O(n × m)이 될 수 있다.
반면 조회된 상품의 productSeq를 Set으로 만들어두면 contains()의 평균 시간 복잡도는 O(1)이다
``` java
Set<Long> existsSeqs = products.stream().map(ProductEntity::getProductSeq).collect(Collectors.toSet());

List<Long> missingSeqs = productSeqs.stream().filter(seq ->  !existsSeqs.contains(seq)).collect(Collectors.toList());

if (!missingSeqs.isEmpty()) {
    log.warn("상품이 존재하지 않는 Seqs: {}", missingSeqs);
    throw new CustomException("PRODUCT_NOT_FOUND", "존재하지 않는 상품입니다.");
}

```

### 고민 4. 존재하지 않은 상품이라면, 상품 번호를 알려주는 게 서비스/보안/디버깅 측면에서 좋은가?

다음 고민은

```
999번 상품은 존재하지 않습니다.
```

처럼 구체적인 productSeq를 클라이언트에게 알려줄 것인지였다.

결정한 방법은 **내부 식별자을 클라이언트에게 노출할 필요가 없다고 생각이 들었다.**
하지만, 서버측에 추적을 하기 위해서는 로그를 남겨야 한다고 생각이 들었다.

로그 레벨는 고민이 들었다.

```
log.warn("상품이 존재하지 않는 productSeq: {}", missingSeqs);
```

시스템의 장애 단계까지는 아니기 때문에 error까지는 사용할 상황은 아니지만, 정상적인 주문 흐름에서는 발생되지 않는 요청이기 때문이다.

다만 존재하지 않는 상품 요청이 정상적인 주문 요청에서는 존재하지 않는 상품 번호가 들어오지 않아야 한다고 판단하기 때문에`warn`단계가 적당하다고 생각했다.
