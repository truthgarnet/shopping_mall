## productSeq 예외처리

이번에는 커스텀 예외처리 하지않은 `상품이 존재하지 않은 경우`에는 어떤 오류가 발생할 지 궁금했다.

ProductEntity를 조회할때, null로 조회되서 Map으로 변환되고 객체의 변수인 getStock()이 이뤄질 때 그때 `NullPointerException`예외가 발생한다.

```java
List<OrderItemRequest> items = orderRequest.getItems();
List<Long> productSeqs = items.stream().map(item -> (item.getProductSeq())).collect(Collectors.toList());
List<ProductEntity> products = productRepository.findByProductSeqInOrderByProductSeqAsc(productSeqs);
   
 for (OrderItemRequest orderItem : orderRequest.getItems()) {
            ProductEntity product = productMap.get(orderItem.getProductSeq());
            int stock = product.getStock();

            if (stock - orderItem.getQuantity() >= 0) {
                stock -= orderItem.getQuantity();
                product.setStock(stock);
            } else {
                throw new CustomException("OUT_OF_STOCK", product.getProductName() + " 는 재고가 부족한 상품입니다.");
            }
            productRepository.save(product);
        }
```

여기에서 내 고민 포인트는

1. 없는 객체를 조회할 필요가 있을까?
2. 그걸 map으로 전환할 필요가 있을까에 대한 의문이였다.

그래서 처음에 생각했던 방식은 existsById였다. 존재하는 객체들만 findBy를 하면 되지 않을 까 생각했는 데 이는 결국 두번 조회하는 꼴이 되기 때문에 불필요한 조회가 일어날 것 같았다.

그래서, findBy를 하되 null 만 찾으면 되지 않을까? 그래서 `List<ProductEntity>`에서 `Optional<ProductEntity>`으로 변경하는 작업을 진행했다.

Optional에서 null이 발생하면 예외처리를 할 수 있는 문법이 있어서 사용했다.

```java
products.orElseThrow(() -> new CustomException("PRODUCT_NOT_FOUND", "존재하지 않는 상품입니다."));
```

**하지만**, Optional은 어느 상품이 존재하지 않는 지는 알 수가 없다.

Optional를 다시 List로 돌려놨다.

findByProductSeqInOrderByProductSeqAsc를 통해서 받아온 객체의 seq들만 existsSeqs로 만들고 request를 통해 받아온 Seq를 비교해서 missingSeqs이 있다면, 상품이 존재하지 않는 Seq를 로그로 출력하게 된다.

```java
Set<Long> existsSeqs = products.stream().map(ProductEntity::getProductSeq).collect(Collectors.toSet());

List<Long> missingSeqs = productSeqs.stream().filter(seq ->  !existsSeqs.contains(seq)).collect(Collectors.toList());

missingSeqs.isEmpty()) {
            log.warn("상품이 존재하지 않는 Seqs: {}", missingSeqs);
            throw new CustomException("PRODUCT_NOT_FOUND", "존재하지 않는 상품입니다.");
        }
  
 Map<Long, ProductEntity> productMap = products.stream()
                .collect(Collectors.toMap(
                        ProductEntity::getProductSeq, product -> product));
```


고민점: 존재하지 않은 상품이라면, 몇번째가 존재하지 않는 상품이라고 알려주는 게 서비스/보안/디버깅 측면에서 좋은가?

결정: 몇번째가 존재하지 않은 상품인지는 로그 단계에서 남기고 서비스에서는 숨기도록 한다.d

결정 이유ddd클라이언트에게 최소한의 정보만d을 주되 서버측에 추적을 하기 위해서는 로그를 남겨야 한다고 생각이 들었다.

로그 단계는 고민이 들었다. 시스템의 장애 단계까지는 아니고, info 단계라고 하기에는 클라이언트가 잘못 전달한 정보로 인해 발생하기 때문에 `warn`단계가 적당하다고 생각했다.
